# Stage 10 — 长期库增量维护（定题后的日常循环）

前 9 阶段回答"这个主题有哪些文献我该读"（一次性批量）；本阶段回答
"定题之后，每天新来的 PDF 怎么进库、进表、进视野"（持续循环）。
来源：李終碩 2026-10-12 分享的工作流，已按本 skill 铁律适配。

## 循环四步

```bash
# ① 新文献进 pdf 文件夹（流水线 pdfs fetch / 手动下载 / 浏览器代取都落在这里）
# ② PDF → MD（递归扫描子目录，幂等：已有 MD 跳过；--force 重转）
lit.py intake tomd  --run <id> --pdf-dir <课题>/references/pdfs
# ③ 提取表追加空行（按 pdf 绝对路径去重，重跑不重复）
lit.py intake table --run <id> --pdf-dir <课题>/references/pdfs
# ④ 模型逐篇读 md 填字段 → 用户看表决定哪篇进 Obsidian 精读
```

目录约定（`intake` 的默认值，可显式覆盖）：

```
references/
├── pdfs/               # 一个 pdf 文件夹（可含子目录，如按 run 分）
├── md/                 # 一个 md 文件夹（同名 .md，含来源路径头注）
└── literature-table.csv # 提取表（utf-8-sig，Excel/WPS 直接开不乱码）
```

## 字段设计（表结构在首次建表时定死）

`--fields fields.json` 传 JSON 字符串数组，**按选题设计**——字段就是论文正文的
骨架预投影。默认核心字段：标题/年份/研究问题/核心方法/主要结论/可复用点/
局限与疑点/与本主题关联/阅读状态。与主题强相关的维度（如"接管信号定义方式"
"干预预算是否量化"）应加进 fields.json。表存在后 `--fields` 不再生效：
换字段 = 归档旧表重建（防止半新半旧列错位）。

填表纪律（继承铁律 9）：
- 只读 md 里真实出现的文字才往字段里写；扫描件转不出正文（tomd 报 failed）
  的行标 `待OCR`，不臆填。
- 表中结论用于写作前，数字级论断仍需回 PDF 定位页节（md 无页码边界）。
- `notes audit` 的自动检查同样适用于从表里长出来的论断。

## 表的用途（李終碩核心洞察）

大量文献的有效信息密度低（工程细节、套话占多数）。表填完后：
- AI 读表即可回答"这篇要干啥、和我的哪条论断有关"，不必每篇开 PDF；
- 框架阶段按表聚合（同字段横向对比 = 综述的对比表雏形）；
- 只有表判定为高价值的篇目才进 Obsidian 精读（`obsidian` 技能已装，
  PDF 直接拖进 vault 阅读批注，快于 WPS）。

## 中文文献（CNKI）通道

学校知网入口合法，但**密码不交给任何 AI 工具**——与 CARSI 同一模式：
1. 用户本人在浏览器登录知网（或校园网 IP 自动认证）；
2. AI 用 browser_exec 在已登录会话里检索、导出题录、逐篇下载（逐篇确认）；
3. CAJ 格式先转 PDF（知网页面可直接选"PDF 下载"的优先选 PDF）；
4. 进 pdf 文件夹后走同一 tomd/table 循环。
知网反爬比 IEEE 强，批量抓取超出个人使用范围，不做。

## 与写作环节的衔接

- 提取表 → `evidence claims-template`：表里的"主要结论/可复用点"是论断池，
  升级成可进稿的 claims 时仍走 claims-check 审计。
- 三维拆解 / 写作语料 / 创新点卡片各节点（MEMORY.md 规则）读 md 即可，
  不再需要每次喂 PDF。
